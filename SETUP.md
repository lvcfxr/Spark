# Spark — настройка сервера (один раз, можно с телефона)

Нужно, чтобы колоды, прогресс и картинки были доступны с любого устройства, где у пользователя есть Telegram.
Пользователям ничего настраивать не надо: при первом открытии Mini App аккаунт создаётся сам, вход — через Telegram, без пароля.
Без этой настройки Spark тоже работает, но всё хранится только на устройстве.

## 1. Проект Supabase (бесплатно)
1. Откройте supabase.com → войдите → **New project**. Придумайте пароль базы (он нам не понадобится) и подождите ~2 минуты.

## 2. Таблицы и правила доступа
1. В репозитории откройте `setup/schema.sql` → кнопка **Raw** → выделите и скопируйте весь текст.
2. В Supabase: **SQL Editor** → **New query** → вставьте → **Run**. Должно быть «Success».

## 3. Функция входа через Telegram
1. В Supabase: **Edge Functions** → создать новую функцию **через редактор в браузере** (Deploy a new function → Via Editor).
2. Имя функции: `telegram-auth` (ровно так).
3. Сотрите пример и вставьте весь текст из `setup/telegram-auth.ts` (тоже через **Raw**).
4. Выключите проверку JWT (**Verify JWT / Enforce JWT verification → off**) — функция сама проверяет подпись Telegram. Нажмите **Deploy**.
5. **Edge Functions → Secrets** → добавьте секрет `TELEGRAM_BOT_TOKEN` = токен вашего бота от @BotFather (того, в котором открывается Spark).
   Токен бота — секрет: только сюда, никогда в файлы репозитория.

## 4. Подключить сайт к серверу
1. **Project Settings → API** (или **API Keys**): скопируйте **Project URL** и публичный ключ **anon** (или **publishable**).
2. Пришлите их в чат Claude — он внесёт их в `config.js` патчем. Или сами: откройте `config.js` в репозитории → ✏️ → заполните:
   ```js
   window.SPARK_CONFIG = { supabaseUrl: "https://xxxx.supabase.co", supabaseKey: "ваш anon-ключ" };
   ```
   Этот ключ публичный по замыслу Supabase — данные защищены правилами RLS. Ключ `service_role` сюда не вставляйте никогда.

## Проверка
Откройте бота в Telegram → кнопка Spark → Настройки: в разделе «Синхронизация» должно быть «Telegram · ваше имя · синхронизировано».
Откройте Spark на втором устройстве (например, Telegram Desktop) — там будут те же колоды и прогресс.

Если пишет ошибку:
- «Подпись Telegram не прошла проверку» — в секрете `TELEGRAM_BOT_TOKEN` токен другого бота.
- «TELEGRAM_BOT_TOKEN не задан» — не добавлен секрет (шаг 3.5).
- 401 при входе — не выключена проверка JWT у функции (шаг 3.4).
- 404 на `changes`, `shared_decks` — не выполнен `schema.sql` (шаг 2).
