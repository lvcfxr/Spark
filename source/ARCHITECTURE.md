# Recall — архитектура (рабочее название)

Приложение с интервальными повторениями: iPhone + Windows/macOS, offline-first, синхронизация в секунды.

## 1. Стек и обоснование

**Выбор: TypeScript-монорепозиторий вместо Flutter.**

| Слой | Решение | Почему |
|---|---|---|
| Ядро (`packages/core`) | Чистый TypeScript, без зависимостей от платформы | FSRS, слияние, импорт — один код и одни тесты на всех платформах |
| iPhone | Expo (React Native), `expo-sqlite` | Нативные UIKit-компоненты, blur, haptics, жесты (Reanimated + Gesture Handler); виджеты и Live Activity всё равно пишутся на Swift |
| ПК | Tauri 2 + React, SQLite через Rust-плагин | ~10 МБ вместо ~150 МБ у Electron; трей, drag&drop, глобальные хоткеи; WebView даёт Markdown/LaTeX/подсветку кода без усилий |
| Бэкенд | **Supabase** (Postgres + Realtime + Storage + Auth) | RLS «из коробки», Sign in with Apple/Google/magic link, SQL удобен для журнала изменений; Firebase хуже подходит для реляционного лога и серверных запросов |
| Монорепо | pnpm workspaces: `core`, `storage` (интерфейс + адаптеры), `app-ios`, `app-desktop`, `supabase/` | |

**Почему не Flutter.** Он даёт один UI-код, но ТЗ само требует, чтобы ПК-версия не была растянутым мобильным интерфейсом (3 колонки, горячие клавиши, ховеры) — значит экраны всё равно разные. Общее — логика, а она в TS шарится полностью. Плюс «ощущение iOS» у RN выше, чем у Flutter, который рисует свои виджеты. Если команда сильнее в Dart, ядро портируется (оно ~600 строк и покрыто тестами).

## 2. Модель данных

Все ID — UUID v7 (сортируются по времени). Поля синхронизируются по отдельности.

- **Deck**: `name, parent_id, emoji, color, preset_id, position, archived, _deleted`
- **Preset**: `name, new_per_day, reviews_per_day, learning_steps, relearning_steps, desired_retention, order, auto_tts, timer, fsrs_w[], algorithm(fsrs|sm2)`
- **NoteType** (шаблон): `name, fields[], card_templates[]` (визуальный конструктор)
- **Note**: `note_type_id, fields{}, tags[], _deleted`
- **Card**: `note_id, template_idx, deck_id, flag, suspended, buried_until, _deleted`
- **ReviewEvent** (append-only): `id, card_id, rating, ts, duration_ms, device_id`
- **Setting**: `key, value` (тема, акцент, цель дня — синхронизируются)
- **Media**: `hash(sha256), mime, size` — файл в Storage по хэшу
- **Производное, не синхронизируется**: `CardState` (phase, step, stability, difficulty, due, reps, lapses) — кэш в локальной БД, пересчитывается из `ReviewEvent`.

## 3. Синхронизация

**Принцип.** Локальная SQLite — источник истины. Любая правка пишется в таблицу `outbox` как `Change` и сразу применяется локально. Сервер хранит упорядоченный журнал.

- **Изменение** `Change{id, entity, entityId, field, value, hlc, deviceId}` — одно поле. Побеждает наибольший **HLC** (гибридные логические часы, `core/hlc.ts`): устойчиво к неверным часам на устройстве.
- **Удаление** — поле `_deleted=true` (надгробие). Правка другого устройства не воскрешает запись; восстановление из корзины — более поздний `_deleted=false`.
- **Повторения** — grow-only множество по `id`; дубли игнорируются. Состояние карточки = `replay(отсортированная история)`. При смене параметров FSRS всё пересчитывается без миграций.
- **Свойства** (проверены тестами): идемпотентность, любой порядок доставки, дубли → одно и то же состояние на всех устройствах.

**Протокол.**
1. Push: клиент отправляет пачки `outbox` через RPC `push_changes(batch)` (Postgres: `INSERT ... ON CONFLICT (id) DO NOTHING`), сервер присваивает монотонный `seq`.
2. Pull: `SELECT ... WHERE seq > :cursor ORDER BY seq`, курсор хранится на устройстве.
3. Realtime: подписка на `INSERT` в `changes` по `user_id` → дотягивание с курсора (секунды). На iOS — тихий push (APNs) для фоновой синхронизации.
4. Сервер **не разрешает конфликты** — он только хранит и раздаёт; одинаковый алгоритм слияния работает на клиенте.
5. Компактация: раз в N дней снапшот состояния + удаление старых `changes` (повторения не удаляются).

**Таблицы Supabase:** `changes(seq bigserial, user_id, id uuid unique, entity, entity_id, field, value jsonb, hlc, device_id)`, `reviews(id uuid pk, user_id, card_id, rating, ts, duration_ms, device_id)`, `devices(id, user_id, name, platform, last_seen)`, `media(user_id, hash, size)`. **RLS:** `user_id = auth.uid()` на всех таблицах и в бакете Storage.

**Медиа:** имя файла = sha256 → дедупликация; загрузка в Storage отдельно от журнала; на iPhone — лениво при первом показе карточки + фоновая предзагрузка колоды по Wi-Fi.

**Без аккаунта:** `user_id` локальный; при входе `outbox` формируется из всей БД, данные не теряются. **Индикатор:** состояние `synced | syncing | error | offline` + число несинхронизированных изменений. **Бэкапы:** локально — ежедневный дамп SQLite (хранится 7 копий); на сервере — PITR Supabase + экспорт в `.apkg`.

## 4. Карта экранов

**iPhone** (таб-бар: Сегодня · Колоды · Статистика · Настройки)
- Сегодня: прогресс-кольцо, кнопка «Учить», «Разминка 5 мин»
- Колоды → Детали колоды (large title) → Список карточек (свайпы, long-press превью)
- Повторение: карточка + свайпы (→ Хорошо, ← Снова, ↑ Легко), кнопки с интервалами, haptics
- Быстрое добавление (share sheet, список «слово — перевод»), Редактор карточки
- Статистика: heatmap, streak, прогноз
- Настройки (grouped list): Аккаунт и синхронизация, Внешний вид, Уведомления, Пресеты, Импорт/экспорт, Резервные копии
- Онбординг (3–4 экрана)

**ПК** (три колонки, как Telegram Desktop)
- Колонка 1: дерево колод (drag&drop), фильтры, теги, корзина/архив
- Колонка 2: список карточек выбранной колоды (мультивыбор, поиск Ctrl+F)
- Колонка 3: редактор + предпросмотр
- Режим повторения (на весь экран, пробел/1–4), палитра команд Ctrl+K, трей, окно настроек, управление устройствами

Акценты: ПК — создание/редактирование/импорт; iPhone — повторение/быстрый захват.

## 5. План по этапам

**MVP** (колоды, карточки, FSRS, синхронизация)
1. ✅ `core`: HLC, FSRS-5 + шаги изучения, реплика (слияние, надгробия, replay) + тесты
2. `storage`: схема SQLite + миграции, адаптеры, outbox, кэш `CardState`, очередь на день
3. `sync`: клиент Supabase (push/pull/realtime), схема SQL + RLS, индикатор статуса
4. `app-desktop`: 3 колонки, редактор базовых карточек, повторение
5. `app-ios`: список колод, повторение со свайпами, haptics
6. Auth (email/Apple/Google), режим без аккаунта

**v1.0:** cloze, реверс, ввод ответа, пресеты и уровень «Расширенные», вложенные колоды, теги и фильтрованные колоды, импорт `.apkg`/CSV, экспорт, статистика и heatmap, медиа-синхронизация, TTS, тёмная тема и акценты, ru/en, границы учебного дня и fuzz, бэкапы, виджеты iOS.

**v1.x:** оптимизатор параметров FSRS, image occlusion, LaTeX/код, Live Activity, умные уведомления, шаринг колод, AI-генерация и объяснения, E2E-шифрование, iPad/Android.

## 6. Спорные требования

- **Сквозное шифрование** несовместимо с серверным поиском, AI и шарингом колод; предлагаю опцию «E2E-режим» (v1.x), где эти функции отключены, а ключ из пароля/recovery-фразы.
- **Sign in with Apple обязателен**, раз есть вход через Google (правило App Store) — учтено.
- **Live Activity, виджеты, share extension** — нативный Swift-код (Expo config plugins); оценивать отдельно, это не «бесплатно» из общего кода.
- **120 fps и 50 000+ карточек:** списки только виртуализированные (FlashList / виртуальный список), очередь дня считается SQL-запросом по индексу `due`, а не в JS.
- **«Почти мгновенно»**: реалистично 1–3 с при активном приложении; в фоне iOS — зависит от системы (тихие push могут задерживаться).
- **Fuzz интервалов** должен быть детерминированным (сид из `card_id + reps`), иначе пересчёт истории даст разные результаты на устройствах. В MVP отключён.
- **SM-2 как опция** удваивает логику пересчёта; предлагаю отложить на v1.x, FSRS покрывает потребности.
